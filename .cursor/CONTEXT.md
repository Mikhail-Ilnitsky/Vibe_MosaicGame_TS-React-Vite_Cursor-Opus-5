# Контекст проекта «Игра-мозаика»

Файл описывает проект и принятые решения, чтобы его можно было подключать как контекст в следующих сессиях.

## Что это

Одностраничная браузерная игра-мозаика без бэкенда: галерея картинок → выбор сложности → сборка пазла из квадратных фрагментов. Техническое задание, по которому сгенерирована первая версия, лежит в [`prompts/INITIAL.md`](../prompts/INITIAL.md).

## Стек и конфигурация

- React 19.3, TypeScript 5.9, Vite 8.3, Tailwind CSS 4.3 через плагин `@tailwindcss/vite` (отдельного `tailwind.config` нет, стили подключаются одним `@import 'tailwindcss'` в `src/index.css`).
- Весь код приложения — в `src/`; конфиги (`vite.config.ts`, `index.html`, `eslint.config.js`, `tsconfig*.json`), workflow и этот файл — вне `src/`.
- ESLint 10 (flat config) с `typescript-eslint`, `eslint-plugin-react-hooks` (правила v7, включая `set-state-in-effect`) и `eslint-plugin-react-refresh`.
- Проверки: `npm run lint`, `npm run typecheck`, `npm run build`.

## Ключевые решения

### Сетка и обрезка (`src/lib/grid.ts`)

- Сложность задаётся числом делений меньшей стороны: `divisions` от 5 до 11 (`DIVISION_OPTIONS`).
- `tileSize = floor(min(width, height) / divisions)`; по меньшей стороне ровно `divisions` плиток, по большей — `floor(большая сторона / tileSize)`.
- Область `cropWidth × cropHeight = cols·tileSize × rows·tileSize` берётся из центра оригинала, `offsetX / offsetY` — половина остатка. Проверено на примерах ТЗ (1000×700): 5 → 7×5 по 140 px, 6 → 8×6 по 116 px, 7 → 10×7 по 100 px.

### Фрагменты на CSS (`tileBackgroundStyle`)

- Картинка не режется физически: каждый фрагмент — `div` с `background-image` оригинала.
- Размер фона считается в «плитках»: `background-size = (imageWidth / tileSize · 100%) (imageHeight / tileSize · 100%)`.
- Позиция учитывает центрирующую обрезку: `X = (offsetX / tileSize + x) / (imageWidth / tileSize − 1) · 100%`, аналогично по Y. Когда картинка делится без остатка (`offset = 0`), формула вырождается в описанную в ТЗ: `background-size: cols·100% rows·100%` и `background-position: x / (cols − 1) · 100%`.
- Фоны считаются один раз через `useMemo` и привязаны к номеру фрагмента, а не к позиции на поле: при перемешивании меняется только порядок элементов в массиве состояния.
- `croppedImageStyle` рисует целую картинку с той же обрезкой (позиция `50% 50%`, так как обрезка симметрична) — используется для просмотра оригинала и для финального экрана победы.

### Адаптивное поле

- Корневой контейнер `h-dvh` + `overflow-hidden`, игровая область `flex-1 min-h-0`, её размер измеряется хуком `useElementSize` (ResizeObserver).
- `fitTileSize` = `min(доступная ширина / cols, доступная высота / rows, tileSize)` — пазл всегда виден целиком без прокрутки и никогда не растягивается крупнее масштаба 1:1.
- Под полем зарезервирована высота (`min-h-28`) под сообщение о победе, чтобы появление текста не меняло размер поля.

### Управление (`src/components/MosaicBoard.tsx`)

- Только Pointer Events (`onPointerDown/Move/Up/Cancel`) + `setPointerCapture`, у плиток `touch-action: none`. HTML5 Drag and Drop не используется.
- Порог перетаскивания — половина отображаемой стороны плитки: меньше — это клик (выделение или обмен), больше — drag.
- Данные жеста живут в `useRef`, в состояние попадает только то, что влияет на отрисовку; плитка `memo`-изируется, смещение передаётся лишь той плитке, которую тащат.
- Позиция под курсором вычисляется из `getBoundingClientRect()` поля и размера плитки; перетаскиваемая плитка поднимается `z-index` и трансформируется `translate3d`.

### Состояние партии (`src/components/PuzzleGame.tsx`)

- `order[позиция на поле] = номер фрагмента`; перемешивание — ровно N случайных парных обменов для N плиток (`shuffleOrder`), с защитой от случайно собранного пазла.
- Ход засчитывается на каждый обмен двух плиток — и для клик-клика, и для drag.
- Победа определяется в обработчике обмена (не в эффекте — этого требует правило `react-hooks/set-state-in-effect`): фаза `flash` включает жёлтую вспышку `animate-flash` на 500 мс, затем фаза `solved` показывает обрезанную картинку без сетки и плавно выводит сообщение и кнопку новой игры.
- Компонент монтируется только когда известны размеры картинки, поэтому начальный порядок создаётся ленивым инициализатором `useState`.

### i18n (`src/i18n/`)

- Контекст (`LanguageContext.ts`), провайдер (`LanguageProvider.tsx`) и хук (`useLanguage.ts`) разнесены по файлам ради правила `react-refresh/only-export-components`.
- Язык по умолчанию: `navigator.language` содержит `ru` → RU, иначе EN. Словари типизированы интерфейсом `Dictionary`, часть строк — функции (склонение «ход/хода/ходов», подпись сетки).
- `<title>` в `index.html` остаётся «Игра-мозаика» по требованию ТЗ; при смене языка меняется только атрибут `lang` документа.

### Деплой

- `vite.config.ts`: `base: './'` для сборки и `'/'` для дев-сервера — один и тот же артефакт работает и локально из корня (`npm run preview`), и в подкаталоге GitHub Pages.
- `.github/workflows/deploy.yml`: `actions/checkout@v6`, `actions/setup-node@v6` (Node 24, кеш npm), `actions/upload-pages-artifact@v3`, `actions/deploy-pages@v5`; job `build` + job `deploy` в окружении `github-pages`. В настройках репозитория источник Pages — GitHub Actions.

## Что стоит помнить при доработках

- Массив картинок в `src/data/images.ts` зафиксирован ТЗ: ссылки прямые и стабильные, динамические генераторы случайных картинок использовать нельзя.
- Размеры картинок берутся из `useImageMeta` (предзагрузка `new Image()` с кешем по URL), без `crossOrigin`, чтобы переиспользовать кеш браузера вместе с `background-image`.
- Правила `eslint-plugin-react-hooks` v7 запрещают синхронный `setState` в теле эффекта — состояние либо инициализируется лениво, либо меняется в обработчиках и колбэках.
